title: "Permissions"
description: "What each permission lets a connected app do."
---

Every credential — an API key or an OAuth grant — carries a set of permissions. A credential can
call a tool only if it holds the permission that tool needs. There are three permissions:

| Permission | Sentence shown to you on the consent screen |
| --- | --- |
| `data:read` | See market data and your analytics. |
| `trade:read` | See your balances, orders and fills. |
| `trade:write` | Place, change and cancel orders with your money. It can never withdraw. |

A credential holds exactly the permissions it was granted. One permission does not imply another:
holding `trade:write` does not also grant `trade:read`.

## How credentials get their permissions

- **A key created in Settings** starts with `data:read`. See [API keys](/auth/api-keys).
- **An OAuth app** gets the permissions it asks for, shown to you on the consent screen before you
  approve. See [OAuth](/auth/oauth).

Because a Settings-created key holds only `data:read`, it cannot call
[`get_portfolio_summary`](/tools/get_portfolio_summary). That tool needs a credential granted
`trade:read`.

<Note>
Credentials that predate this permission model keep working exactly as before, so nothing you
already connected was narrowed by it.
</Note>

If an app calls a tool it doesn't hold the permission for, the call is refused — it doesn't revoke
or change anything. The app can keep calling the tools it does hold.
